# CloudCannon trial setup (staging only)

- CloudCannon Site: connect `snayana-hub/athidhi-preview` on the `Content-Edits` branch. Production remains GitHub Pages from `main`.
- Keep the CloudCannon Site hosted/build-enabled to support the Visual Editor's preview. Do not use Headless Mode, which disables builds and hosting.
- The `Pages` collection is intentionally limited to `index.html` for this first trial. The homepage supports Visual + Data editing; its explicit editable regions cover the DE/EN hero heading and introduction plus story image source/alt. SEO title and description are front matter fields configured in the Data Editor and feed the page title, description, and social cards. (`<head>` metadata is not a visible inline region.)
- The global editor default remains Data-only; the homepage collection and `file_config` explicitly allow Visual + Data. `_enabled_editors` cannot disable Source Editor; account permissions are separate. If the plan permits custom roles, deny SEO team `site:source-editor:write` and `site:file:write`. If not, keep the staging-only `Content-Edits` branch and Siri's merge as the ship gate. Do not invite editors until roles/permissions are checked.
- `_includes/tracking-codes.html` is a shared empty include wired into the homepage head. No tracking provider or ID is included; add one only after owner approval. Future pages can include the same partial if the owner wants site-wide tracking.
- A successful CloudCannon build is required for the Visual Editor to preview output. The repo contains static HTML plus Jekyll/Liquid front matter, so CloudCannon's Site build settings should be checked/set to render the same homepage output and use its built output path. Build configuration lives in CloudCannon Site Settings, not this repo config. Do not enable CloudCannon production publishing; only `Content-Edits` is in scope.
- All edits stay on `Content-Edits` and require Siri's GitHub merge before anything reaches live `main`. Do not publish from CloudCannon to production.
